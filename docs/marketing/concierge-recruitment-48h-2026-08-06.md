# Skill Evals Workshop Concierge｜48 小時招募執行表

日期：2026-08-06

本文件承接 `concierge-workshop-2026-08-06.md`。目標不是取得流量，而是找到 10 位目前真的正在做 Skill／repo 採用決策的人，並如實驗證是否出現 3 個 `decision-changed` 案例。

## 2026-08-05 現況

- [Luma 活動頁](https://luma.com/claude-lbtz)已停止報名；不能把新增 RSVP 當作招募來源。Hugo 必須已有入場資格，或由主辦人確認可入場。
- 議程只有 `20:30–21:30` 一小時自由交流。單一主持人的完整 session 需要約 20 分鐘（訪談 15 分鐘＋紀錄／重置 5 分鐘），現場合理上限是 3 次，不是 8 次。
- 因此採「活動前完成 6 次、現場最多 3 次、活動後另約 1 次」；若有第二位依同一腳本受訓的主持人，才提高現場上限。
- `3 decision-changed` 是驗證結果，不是要參與者配合的招募配額。10 次後不足 3 次就照實判定假設未通過。

## 合格受訪者

邀請前先確認四件事：

- 最近確實在考慮某個 Skill、plugin 或公開 repo。
- 未來 7 天內有真實任務會用到它。
- 能提供不需登入的公開 HTTPS URL，且理解報告會永久公開。
- 看報告前能先選 `install / try / skip` 並說明理由。

任一項不成立，不計入 10 位合格訪談。

## 48 小時節奏

### 今天

- 前 2 小時：列 18 位具名候選人（8 warm／4 workshop／2 referral seeds／4 online backup），依相關性選 12 位一對一邀請。
- T+2–8 小時：完成篩選與排程。
- T+8–12 小時：先跑 2 次完整訪談，驗證腳本和紀錄流程。
- 硬指標：`12 邀請 / 8 回覆 / 6 合格 / 4 排程 / 2 完成`。

### 明天 Workshop

- `09:00`：確認 8 個正式時段與 4 位候補；缺公開 URL 或有效 pre-decision 者立即替換。
- `10:00–15:30`：完成 4 位 warm／referral 遠端訪談，使活動前累計達 6 次。
- `18:30–19:00`：報到只做 60 秒篩選與排程，不在隊伍中完成訪談。
- `20:30–21:30`：單主持人最多完成 3 次，每次 15 分鐘＋5 分鐘紀錄／重置。
- 第 10 次在主辦人允許的活動後空間或遠端完成；若無法安全完成，就明確延後，不壓縮訪談。
- 活動後立即做 30 分鐘收斂，不先改產品。
- 累計硬指標：`10 位合格完成 / 10 個有效 pre-decision / 10 個公開 URL / 3 個 decision-changed`。

若連續三人無法理解產品承諾、決策分類或永久公開提醒，立即暫停招募，不能靠訪談者解釋把流程硬帶完。

一人一列、一人只計一個主要 URL。

| P01 |  | 否 / 是 | 否 / 是 |  |  |  |  | 否 / 是 | 否 / 是 | 否 / 是 | 否 / 是 | 否 / 是 |

計數規則：

```text
Interviews = qualified 且 completed 的不同參與者數
Changed = Gate 1 AND Gate 2 AND Gate 3 的不同參與者數
Pass = Interviews >= 10 AND Changed >= 3
```

- `10 interviews / <3 changed`：價值假設未通過，不能把 clarified 改算成 changed。
- `<10 interviews`：樣本尚未完成，結論是不充分。
- 24 小時 follow-up 只確認實際行動，不能取代當場 gate。

## Gate 通過前暫停

- 付費廣告、retargeting。
- Product Hunt、Hacker News 或大型公開 launch。
- 泛 X／LinkedIn 貼文與流量型內容。
- SEO／大量 programmatic report pages。
- 自動化 cold email、名單抓取。
- Influencer、PR、活動贊助。
- Affiliate、獎勵式 referral。
- 大規模社群 partnership 或 marketplace 上架。

第一次通過 gate 後，先用另一批 10 位非熟人 cohort 重複驗證，再決定是否擴大曝光。
